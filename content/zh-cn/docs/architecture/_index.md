一个典型 AI Infra 平台可以拆成数据、训练、模型资产、推理服务、平台控制面和可观测性几层。

## 核心链路

```text
数据源 -> 数据处理 -> 训练任务 -> 模型仓库 -> 推理服务 -> 业务调用
                    |             |             |
                    v             v             v
               调度与资源       版本治理      指标与告警
```

## 关键组件

- 资源层：GPU/CPU、网络、存储、Kubernetes、调度器和配额。
- 数据层：数据集管理、特征处理、缓存、数据质量检查和访问控制。
- 训练层：任务提交、分布式训练、实验追踪、检查点和容错恢复。
- 模型层：模型注册、版本、元数据、评测结果和发布策略。
- 推理层：模型加载、批处理、路由、弹性伸缩、灰度和回滚。
- 运维层：指标、日志、链路追踪、成本分析、SLO 和故障复盘。

## 架构设计关注点

- 资源利用率：GPU 是否被数据读取、通信或调度等待拖慢。
- 隔离性：多租户任务之间如何隔离资源、权限和依赖。
- 可复现性：训练代码、数据版本、镜像和参数是否能重放。
- 可发布性：模型从实验到上线是否有清晰的审批和回滚路径。
- 可观测性：问题发生时能否快速定位到数据、代码、资源或依赖。
