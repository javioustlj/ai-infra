推理服务把模型能力暴露给业务系统。它需要同时处理延迟、吞吐、成本、稳定性和发布治理。

## 基本链路

```text
Client -> Gateway -> Router -> Model Runtime -> Accelerator
              |          |             |
              v          v             v
          Auth/Quota   Canary       Metrics
```

## 关键设计点

- 模型加载：冷启动时间、权重格式、显存占用和多模型复用。
- 请求路由：按模型版本、租户、地域、负载和灰度策略分发流量。
- 批处理：通过 dynamic batching 提升吞吐，但要控制排队延迟。
- 弹性伸缩：基于 QPS、队列长度、GPU 利用率和 P95/P99 延迟扩缩容。
- 降级策略：限流、超时、缓存、回退模型和错误隔离。

## 需要持续跟踪的指标

- 请求量、错误率、超时率。
- P50、P95、P99 延迟。
- GPU 利用率、显存使用、batch size 分布。
- 队列等待时间和模型执行时间。
- 单次请求成本和单位 GPU 小时吞吐。
